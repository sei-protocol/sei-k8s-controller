# Recovering archives published by an older sidecar

An older publisher could upload an incomplete snapshot and record the upload as successful. On its next run, the upgraded publisher verifies and uploads its newest completed local snapshot even if the old checkpoint recorded the same or a higher height. It keeps a higher shared marker because another publisher may have produced a valid archive there.

Before the first upgraded run, preserve each publisher's deployment version and `<home>/.sei-sidecar-last-upload.json`. The current `archiveVerificationVersion` records verification of a local archive for its bucket and chain; it does not validate the shared prefix. Unverified history is excluded from duplicate suppression and startup upload metrics. An empty local snapshot list remains a successful no-op with a warning, preserving its checkpoint and existing remote objects.

1. Pause every publisher for the affected chain and suspend restore jobs and external readers that use the destination. Record the contents and ETag of `{chainID}/state-sync/latest.txt`. List all archive keys under `{chainID}/state-sync/`, including subdirectories. Record each suspect object's height, ETag and S3 version ID when available.
2. Download the recorded versions of the suspect archive and each proposed replacement. In a separate, empty node home for each archive, confirm the SDK or a compatible node can apply all chunks and recover the application state at the advertised height. A successful download or extraction alone leaves application recovery untested. If no usable replacement is available, keep restores paused and obtain one from a healthy producer.
3. Preserve a copy of each confirmed bad object **outside the entire chain state-sync prefix** and verify that the copy contains the inspected bytes. Then remove the bad key from the current listing or replace it with a verified archive for that same height. Use the inspected ETag as the S3 `If-Match` condition on the change. Stop and inspect again if the object changed. Re-list the full prefix. The sidecar can select a numeric archive in a quarantine subdirectory under the same prefix.
4. If `latest.txt` points to a confirmed bad or missing archive, set it to the highest remaining verified height using its observed ETag, or use `If-None-Match: *` to create an absent marker. Preserve a higher marker that already points to a verified archive. Check the marker and the archive it names for external readers.
5. Exercise the ordinary restore into a fresh home and confirm the application height. By default the sidecar selects the highest archive it lists. For a restore with `targetHeight`, it selects the highest listed archive at or below the cap. Check the affected caps before resuming readers and publishers. A higher valid upload can restore the default path while an older damaged archive remains selectable under a cap.
